# CrispASR integration — local evidence

Environment: Windows x64, Intel i7-12700H, NVIDIA RTX 3060 Laptop GPU.
CrispASR v0.8.41 at `340d7085eaa53c40a46dcb73a6d3d0448a480006`, ggml at
`2f5a80d258c46e6ac8eee95f1328c0f58376d7ee`; Vulkan SDK 1.4.363.0.

## Real-speech native smoke

Fixture: the pinned CrispASR checkout's `samples/jfk.wav` (11 s of real JFK
speech). Each model's SHA-256 was verified before loading. Harness:
`sidecar/crispasr/tests/smoke.py`; reports contain counts/timings, not transcripts.

Latest sequential Vulkan runs, with the final default schedules:

| Model | Initialize/warm | Batch decode after input | First live text | Final after last chunk | Batch / live WER |
|---|---:|---:|---:|---:|---:|
| Parakeet Ultra Q8_0 | 908 ms | 321 ms | 1,202 ms | 413 ms | 0% / 0% |
| R2T2 Q4_K | 2,210 ms | 1,326 ms | 1,558 ms | 185 ms | 0% / 0% |
| R2T2 Q8_0 | 3,507 ms | 1,191 ms | 1,655 ms | 643 ms | 0% / 0% |

These are native-protocol measurements with a realtime-paced recording input,
not hotkey-to-cursor numbers. They exclude microphone startup, post-roll,
clipboard delivery and Polish. The recording result consumes the finished
stream instead of adding another whole-file decode. This single fixture proves
the integration runs; it does not establish general accuracy rankings or
multilingual parity.

CPU inference was also exercised: Ultra Q8 batch/live matched the reference;
R2T2 Q8 offline Auto and Q4 explicit English matched it. Q4 offline Auto returned
empty text on the same speech, while its native R2T2 streaming recipe succeeded.
The shipped adapter retries an empty Auto offline result once through that
recipe, without forcing a language. The regression harness then passed Q4 Auto
on CPU and Vulkan. Exact digital silence does not trigger that extra retry.

## Scheduling findings

- The upstream 160 ms R2T2 schedule re-encodes accumulated audio. It took about
  108 s for the 11 s clip on CPU. A supported 2 s CPU schedule reduced the paced
  run to about 16 s, with the same words.
- Q8 also fell behind capture at 160 ms on the laptop GPU. A 640 ms GPU schedule
  kept up and finalized about 0.6 s after the last chunk. GPU Q4 also passes with
  that schedule. Offline retries use 2 s steps because they need no live updates.
- Parakeet previews preserve full context and stay tentative; one complete
  decode owns the final. No neural VAD or extra language-ID model is loaded.
- Qwen's upstream warmup is a no-op; the sidecar explicitly warms its encoder
  and a bounded decoder pass during preload. Silence used for warmup is not
  used as an accuracy benchmark.

## Contract checks

- Native PCM codec: correct little-endian conversion, invalid base64/NaN
  rejection, and finite resampler overshoot retained. CPU and Vulkan CTest pass.
- Native protocol: invalid JSON, missing model, stale session, unknown command,
  clean shutdown and content-free diagnostics pass for both binaries.
- Rust: verified downloads, atomic publication, PCM conversion/tail flush,
  generation/model/language final-result ownership, and backlog invalidation.
- Auto language: settings, native menus, Whisper CPU/preview/Vulkan parameter
  mapping, detected-language metadata and source-language-preserving Polish.
  Startup validation now uses spoken-language policy instead of treating Auto
  as an invalid output-language code.
- Windows shipped bindings: native C/Rust ABI and API tests pass with libclang
  unavailable. The application and Whisper Vulkan Cargo projects use the same
  patched, checksum-pinned sys crate. ARM64 declarations are generated but
  native ARM64 ABI execution remains unverified.

## Remaining hardware smoke

`NEEDS-SMOKE`: packaged microphone → post-roll → cursor delivery, cancellation
and back-to-back dictation on macOS; native Apple Silicon/Intel builds; Windows
ARM64 ABI execution; long/multilingual/quiet real-speech corpus runs. CrispASR
is offered for local desktop, upload and CLI transcription; LAN hosting is not
advertised until the remote-host adapter supports it.
